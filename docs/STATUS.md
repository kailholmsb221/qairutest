## Решения, принятые при старте (отличия от docs/ARCHITECTURE.md)

| Что | Как сделано | Почему |
|---|---|---|
| Программа помещений | **Чертежи владельца, стены дословно** (2026-09-18): `packages/map-data/plans/floor-{1,2}.svg` (Illustrator: стены — штрихи, подписи — текст) → `apps/map-editor/tools/svg2plan.py` → `tools/traced/<этаж>.json`: штрихи сохраняются как есть (`strokes`, кривые Безье не аппроксимируются) и рисуются экраном как стены; помещения между ними вычисляются (планарная сеть, мостики через проёмы, полигонизация, коридор с дырами-островами в `holes`); подпись называет грань, в которой стоит. Идентичность — `tools/floor{1,2}.ts` → `gen:floors` → `packages/map-data/vector`. Оба этажа ориентированы одинаково — дугой фасада вниз (1 этаж повёрнут на 90°: вход сверху; 2 этаж — как нарисован), поэтому в 2.5D-стопке они смотрят в одну сторону; подписи 1 этажа расставлены по фото стенда (на чертеже их нет), безымянные грани 1 этажа типизированы по цвету фото | Владелец отверг трассировку фото 2026-09-16 и принёс готовый чертёж 2 этажа (`fll2.svg`) и чертёж 1 этажа (`1 fl.svg`), 1 этаж должен выглядеть как его скриншот; первоначальный поворот 2 этажа на 180° отменён 2026-09-18 по его же просьбе («этажи должны смотреть в одну сторону») |
| Редактор расписания | Админ-панель (⚙ в тикере → 📅): сетка «пары × дни недели» для выбранной аудитории, «+» в свободной ячейке добавляет шаблон занятия (дисциплина, преподаватель, группы, тип, чётность недель), ✕ удаляет. API: `GET /admin/catalog`, `GET/POST /admin/lessons`, `DELETE /admin/lessons/{id}` (X-Api-Key); сервис отклоняет двойное бронирование аудитории/преподавателя/группы (409), после изменения сбрасывает кэш каталога и рассылает новый снимок по SSE. Ключ панели берётся при сборке (`NEXT_PUBLIC_ADMIN_API_KEY`) или на лету через `/api/admin-key` (демо) | Владелец попросил «админ-панель, где можно ставить расписание». Шаблоны `lessons` — единственный источник расписания, поэтому движок/табло/карта ничего не знают о панели |
| Коды аудиторий | `packages/map-data/room-codes.json`: **27 расписуемых** — все пронумерованные (100–103, 102A, 200–204, 204A, 206, 209, 213–215, 217–224, 226, 227, AI-LAB); дубли подписей получают суффикс A (102A, 204A); WC-1/WC-2/CR/CINEMA/CAFE, узкий 225 и атриум VOID-2 — без расписания, но кликабельны; остальные — `code = id` карты | Решение владельца 2026-09-18: расписание у всех пронумерованных кабинетов, кнопки — у всех подписанных помещений |
| Крылья | enum `west \| east \| core` вместо `north \| south \| core` | Реальный план — ландшафтный (ядра сверху, дуга фасада снизу), крылья слева/справа от центрального холла (x 700–900) |
| Источник геометрии | `vector/*.json` → `scripts/vector2map.ts` → `vector-map.json` (что рисуем) + `building-a.json` (идентичность) | SVG-трассировка не нужна: планы уже в топологической модели редактора; svg2map заменён на vector2map |
| Палитра | Токены = палитра карты (`#0d1520`, cyan `#4fd1ff`, статусы green/orange/yellow/blue), не fallback-токены промта | Один цвет — одно значение и на карте, и на табло; карта неприкосновенна |
| RoomShape | `<path data-phase>` + CSS-переходы вместо `motion.path` | 300 путей; CSS дешевле и не меняет рендер редактора |
| Zoom/pan | В фокус-виде сохранены колесо + перетаскивание из редактора | Ландшафтный план 1600×1000 с мелкими подписями |
| Зазор этажей | `max(72px, 0.32 × высота слоя)` | При 72px два больших ландшафтных этажа перекрываются |
| Порты по умолчанию | api 8090, postgres 5434, web dev 3000/3100, compose-проект `campuslive-map` | На машине разработчика 8080/5432 заняты другим стеком |
| Пакет `internal/service` | Добавлен (кэш каталога + снимка, admin use-cases) | §8.1 архитектуры описывает `service.Board`, но дерева для него не было |
| `Snapshot.announcements`, `DayTimeline.slots`, `TimeInfo.localDate/weekNumber/parity` | Добавлены в контракт | Тикер получает объявления при подключении; шкала времени знает слоты; шапка показывает неделю/чётность |
| Фокус-вид: `viewBox` = габариты всех помещений + поле (в пропорции 1600×1000), слой без CSS-scale и без `will-change` | Вместо `scale(1.12)` на композитном слое и вместо фиксированного ×1.12 | Слой с `will-change`/scale растрируется один раз и растягивается — план «плыл» при зуме; векторный zoom всегда чёткий. Чертежи заполняют viewBox почти целиком, фиксированный ×1.12 обрезал бы края здания |
| Модель плана: `holes` у помещения и `strokes` у этажа | `Room.holes: BoundaryRef[][]` (острова внутри коридора), `FloorPlan.strokes: {id, d, exterior}` (path data чертежа дословно) | Коридор вокруг островов остаётся одним помещением (заливка `evenodd`), а экран рисует кривые чертежа, а не их дискретизацию; мостики через проёмы (`virtual`) не рисуются |
| Клик по этажу в стопке = клик по любому помещению; выделение без обводки | Убраны прозрачная кнопка `floor-hit` и белый `selection-outline`/focus-stroke | Невидимая кнопка ловила фокус-рамку; выбранная аудитория лишь чуть светлее |

## Известные ограничения

- Коды и расписуемость в `room-codes.json` — по решению владельца от 2026-09-18 (все пронумерованные); чтобы, например, снять расписание с 102A/213/214, достаточно поправить `schedulable` и `pnpm map:build && pnpm seed`.
- Названия кабинетов 2 этажа, которых не было раньше (204, 204A, 217, 219, 227), — «Аудитория»/«Кабинет»; названия задаются в `apps/map-editor/tools/floor2.ts` (или `name` в `room-codes.json`).
- Карта — чертежи владельца: на чертеже 1 этажа нет подписей, поэтому позиции 100–103, WC, CR, Cinema, Cafe заданы в конфигурации `svg2plan.py` (`anchors`) по фото стенда; безымянные помещения 1 этажа получили тип по цвету фото (`types`), остальные — «Помещение». Правки: геометрия — в SVG (`packages/map-data/plans/*.svg`) → `python apps/map-editor/tools/svg2plan.py` (numpy, opencv-python, shapely, svgelements, Pillow), идентичность — `tools/floor{1,2}.ts`, затем `gen:floors` → `pnpm map:build`. Точки `at` в таблицах идентичности и в конфигурации — в координатах viewBox 1600×1000; при смене поля вписывания (`MARGIN`) их нужно пересчитать (QA-рендер печатает полюс каждой грани).
- Дверные проёмы — невидимые мостики (`virtual`); двери/лестницы/лифты как отдельные символы на чертежах не обозначены (лестничные марши 1 этажа — штрихи чертежа).
- «Закрытая зона» 1 этажа и прочие тёмно-синие на фото помещения без подписи имеют `type: hall` (синяя заливка, как просил владелец); чтобы сделать их серо-синими служебными, достаточно сменить тип на `service`.
- `pnpm test` в корне падает на `@campuslive/map-data#test` (vitest без тестовых файлов) — так было и до переоцифровки; остальные пакеты зелёные.
- `golangci-lint` не установлен локально — запускается только в CI.
- Chrome performance trace 60 fps для фокуса этажа не прикладывался (нет headed-браузера в сессии); анимируются только `transform`/`opacity`, фильтры — один `drop-shadow` на группу внешних стен и один `feGaussianBlur` на контур этажа.
- Прод-сборка Next с `output: standalone` включается переменной `NEXT_STANDALONE=1` (Docker/CI): на Windows без developer mode pnpm-симлинки не создаются.
